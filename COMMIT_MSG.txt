Read a KV index key instead of listing on every cron run

The per-minute scheduled handler opened with SUBS.list(), which spent all
1,000 free-plan list operations by roughly 16:40 UTC and then threw for
the rest of the day, silently killing every check-in until midnight.

Track the registered endpoints in a single index key and read that
instead. Reads have a 100,000/day budget, so a per-minute poll fits with
room to spare. The index seeds itself from a one-off list() when absent
so already-registered devices survive the deploy.
